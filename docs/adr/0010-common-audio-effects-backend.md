# 统一音声后端并接入播放音效

播放音效以 Android、iOS、macOS、Windows 和 Linux 为目标。
音声播放统一采用 media_kit/mpv。
验证范围包括基础音效、两种双耳扩宽，以及现有播放契约。

## 全平台原生产物与验收

按 2026-11-10 的确认，五个平台使用同一版本的 mpv 和 FFmpeg。
统一升级到稳定发布版本。
升级目标为 mpv 0.42.0 和 FFmpeg 9.0.2。
各平台锁定相同的 mpv 和 FFmpeg 源码提交，并共用音效补丁。
Android、iOS、macOS、Windows 和 Linux 均须通过原生库与应用构建。
播放音效输出验收必须使用发布包实际交付的原生库。
处理后的输出沿用现有测试的数值容差。
旁路和零强度输出仍须逐样本一致。
五个平台全部通过构建和输出验收，才算本轮完成。
继续不做真机验证，使用 CI、主机和模拟器检查。
iOS 输出在同源模拟器库上验收。
iOS 设备库须通过构建、架构与最低系统版本检查。
iOS 设备实际输出保留为未验证，不作为本轮完成的条件。
本决定取代下文 Android 优先阶段的交付条件。

按 2026-11-12 的确认，macOS 原生库和应用只支持 Apple Silicon arm64，最低 macOS 版本为 11.0。
iOS 真机和模拟器原生库只保留 arm64，真机最低版本为 13.0。
iOS arm64 模拟器产物继续通过 14.0 系统版本边界检查。
不再生成 macOS Intel 或 iOS 模拟器 x86_64 原生库。
Android 只发布 arm64-v8a APK，x86_64 原生库用于模拟器测试。
Linux 只构建和发布 x64，停止发布 ARM64。

## 迁移背景与 Android 优先阶段

现有音声后端分为 Media3、AVPlayer 和 mpv。
共享 C/C++ 内核能复用算法，但仍需维护三种接入方式。
统一后端可以共用处理链，代价是重新验证预加载、跳转与系统音频行为。

按 2026-11-09 的确认，不再执行真机验证。
该阶段的交付重点为 Android。
Android 原生库、APK 构建和自动化测试必须通过。
其他平台复用处理链。
其他平台的构建与运行缺口单独记录，不阻塞本轮交付。
原生构建与后端迁移并行推进，再完成两阶段播放音效。
Windows 主机实际输出及自动化测试继续执行。
已有 Android 实际输出证据保留，未执行的设备检查单独记录。
iOS、macOS 和 Linux 的能力单独记录，缺少证据时保持未验证状态。
场景效果以 Eara 的固定行为为基准。
单声道扩宽必须包含瞬态与包络保护。
原锁定库缺少所需滤镜，原生构建补齐 Windows、Android 和 Apple 库。
构建保留现有最低系统版本，并记录源码、工具链和依赖版本。
补齐滤镜后，验证原生构建和 Windows 主机实际输出。
构建或自动化验证失败时，修复后重新验证。
不自动新增独立原生 DSP 或更换引擎。

迁移保留独立的视频实例和现有最低系统版本。
[ADR 0003](0003-independent-audio-cache.md) 的播放与后台缓存分离原则继续适用。
迁移后，以新后端的等效预加载取代原 Media3 接入方式。
后端保护只能在替代行为验证后调整，不能通过删除保护测试完成迁移。

iOS 和 macOS 的原锁定库也只启用 `overlay` 和 `equalizer`。
Apple 构建沿用固定配方，补齐同一套滤镜。
该阶段的最低版本曾设为 iOS 13 和 macOS 10.15；2026-11-12 的决定将 macOS 最低版本改为 11.0，并移除 Intel 原生库。

## 运行时参数恢复

mpv 在同一来源内切换采样率时会重建 lavfi 图。
重建会重新解析最初的滤镜字符串。
仅发送实时命令会让参数退回最初的值。
格式通知早于图就绪，不能作为 Dart 补发命令的依据。

原生 lavfi 实例缓存最后一次成功执行的效果参数。
缓存仅接受已知目标的有限数值参数。
图重新配置后，原生实例先恢复参数，再接收音频。
图销毁时释放缓存。
切换来源与显式跳转仍由应用安装最新设置快照。
实时调节保持使用同一实例，不重新加载来源。

同源主机检查已验证采样率切换后的参数保留。
结果及平台缺口见[播放音效验证](../development/audio-effects-validation.md)。
