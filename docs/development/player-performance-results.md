# Android 播放器性能报告

2026-09-17，以 v4.4.16（`2704a5a`）为基线。Android 原始文件直播放消除了
大 WAV/FLAC 的整文件复制：下载 FLAC 的请求至 READY 中位数从 3731ms 降到
99ms，WAV 从 4384ms 降到 173ms。字幕跟随帧耗时 P95 从 21.001ms 降至
14.482ms，改善 31.0%。连续请求由同一个协调器处理，只有最新目标可以提交
曲目、队列索引、媒体信息和会话记录。性能验收尚未全部通过，具体结果如下。

## 环境与口径

- USB 真机：Huawei ABR_AL60，Android API 31，1224×2700，DPR 3.375。
- Flutter 3.44.7 / Dart 3.12.2，仓库锁定的 just_audio、Media3；未新增或升级依赖。
- 使用独立测试安装 `com.meteor.kikoeruflutter`，未覆盖用户原应用。测试结束后已
  移除临时测试应用及其素材/缓存，保留手机上的原始音频和主机上的测量报告。
- 音频触感反馈关闭。每轮启动前 thermal status 为 1 或 2，未更改系统显示模式。
- 动画预算按每个场景开始时 Android 当前 Display 刷新率计算，本次 UI 场景为
  60Hz，即 16.667ms。音频轮次的 Flutter 启动刷新率不用于动画验收。
- 素材：512MiB PCM WAV、用户提供的 473201145 字节 FLAC、两者的完整缓存，
  以及三首约 5MiB 的小 WAV。中文/日文路径和同名字幕另有设备用例。
- 基线使用独立源码副本，只加入同一份测试和测量入口，生产行为保持 v4.4.16。
  每组五轮，进程每轮重启；首次展开和重复操作分开记录。
- 表内时间单位为 ms。音频每种大文件和离开场景 n=10；P95 采用
  `ceil((n-1)×0.95)`，n=10 时等于最大值。

完整步骤见 [运行文档](player-performance.md)。本地原始报告保存在
`build/player_performance/reports/`，聚合数据为
`build/player_performance/final_summary.json`。公共文档使用匿名素材标识。

## 音源加载

取 `baseline_user_20..24` 与 `candidate_final_audio_100..104`。READY 表示
源加载完成；进度流含 just_audio 时间外推，不能替代扬声器首个采样的测量。

| 进入目标音源 | 基线中位数 / P95 | 候选中位数 / P95 | 中位数 / P95 改善 |
| --- | ---: | ---: | ---: |
| 下载 WAV | 4384.181 / 21068.734 | 173.237 / 376.125 | 96.0% / 98.2% |
| 下载用户 FLAC | 3731.273 / 9594.651 | 99.336 / 256.259 | 97.3% / 97.3% |
| 完整缓存 WAV | 91.553 / 114.014 | 73.655 / 90.637 | 19.6% / 20.5% |
| 完整缓存用户 FLAC | 73.850 / 79.851 | 79.313 / 89.654 | -7.4% / -12.3% |

文件准备阶段的中位数/P95：WAV 从 4164.260/20494.444 降至
10.197/17.956，用户 FLAC 从 3449.662/9172.744 降至 13.072/21.524。
Android 直接将原始路径传给 Media3，Unicode 文件名与同名字幕无需 MPV 副本。

完整缓存没有原来的整文件复制，收益不同。候选在换源前暂停当前播放，确保被
取消的源不会在 READY 后短暂发声；完整缓存 FLAC 本轮有小幅回退，未达到 25%
改善门槛。原生阶段仍由 `setFilePath` 聚合计时，未细分解码器内部工作。

## 动画

取 `baseline_final_ui_70..74` 与 `candidate_lyric_ui_110..114`。UI、raster 和
帧耗时列分别是五轮单轮 P95 的中位数；帧耗时为每帧 `max(UI, raster)`。
卡顿比例合并五轮帧计数，不等于单个线程 P95 的超预算比例。

| 场景 | UI P95 基线→候选 | raster P95 基线→候选 | 帧 P95 基线→候选 | 卡顿比例基线→候选 |
| --- | ---: | ---: | ---: | ---: |
| 冷进程首次展开 | 12.969→13.305 | 8.066→7.860 | 15.069→13.305 | 3.933%→3.889% |
| 重复展开/收起 | 8.120→8.212 | 8.916→9.604 | 12.385→12.219 | 4.095%→3.780% |
| 拖拽反向/回弹 | 5.717→5.994 | 8.863→7.813 | 10.673→11.055 | 3.596%→3.330% |
| 拖拽展开交接 | 10.436→10.067 | 10.020→10.355 | 18.358→19.521 | 5.278%→5.457% |
| 连续切页 | 2.167→2.272 | 12.698→12.994 | 13.304→13.934 | 2.312%→3.043% |
| 字幕跟随 | 6.206→9.580 | 12.363→9.986 | 21.001→14.482 | 6.524%→3.944% |
| 字幕手动滚动 | 7.335→7.891 | 10.641→11.526 | 10.814→11.593 | 0.543%→0.771% |

字幕跟随的五轮候选帧 P95 均在 16.667ms 内，最差轮 16.376ms；基线最差轮
22.824ms。UI 平均耗时 2.963→2.588ms，超预算 UI 帧 95/2008→77/2079，
超预算 raster 帧 37→7。UI P95 上升与尾部样本分布有关，不等于平均重建成本上升。
全部场景合并卡顿帧为 362/9203→327/9291（3.933%→3.520%）。

各场景 UI/raster P95 的五轮中位数均在预算内，但重复展开的 raster、字幕跟随的
UI、手动滚动的 UI/raster 相对基线回退超过 5%；交接、切页和手动滚动的卡顿
比例增加，交接帧 P95 也未达预算。因此不能宣称整体动画验收通过。

动画时长、曲线、Hero 轨迹、模糊、阴影与布局保持不变。隐藏页暂停动画时同时
保留正在参与转场的两个页面；隐藏字幕只记录最新播放行，重新可见时立即对齐。
七张新增关键帧来自 v4.4.16，原黄金图保持不变。保留实测有效的字幕更新范围优化。

## 正确性与回归

- Dart 静态分析通过；Android arm64 Profile APK 构建通过。
- 请求协调回归 15 项通过，涵盖 A 加载时连续下一首至 C、加载中暂停/停止、
  初次加载停止后恢复、替换队列、清空原生停止屏障、恢复历史、进度保护和缓存取消。
- 真机 `candidate_checks_90` 共 55 次成功音源加载（含初始加载，即超过 50 次切换）。
  下载 WAV、用户 FLAC 及其完整缓存四种 A/B/C 并发场景均只发布 C，无错误；
  完整缓存保留。最新目标至进度流推进分别为 165.249、161.181、133.665、149.674ms。
- `candidate_listen_95` 连续播放用户 FLAC 120 秒，进度推进 120015ms，结束时仍在
  播放；人工实听反馈单独记录。
- 计时/清单、性能协议和入口回归 25 项通过；字幕交互与关键帧 20 项通过。
  重新可见时最新行的居中位置和无滞后滚动另有几何断言。
- 现有交互测试组 90 项通过；一项主页面字幕预览滚动断言在未改动的基线也失败
  （期望偏移 0，实际 76）。
- 现有静态黄金图四项在基线和候选均失败，四张实际输出逐像素相同。原基准图未
  更新。现有封面过渡中间帧以及新增七张路由关键帧通过。

## 限制与后续

未通过项为动画逐场景的回退/卡顿门槛，以及完整缓存和稳定播放后离开大文件的
25% 收益门槛。人工实听反馈尚未收到。测量只覆盖本台 Android 手机；未改变
其他平台的 MPV/Darwin 路径处理。原生加载仍需更细的解码器计时，才能定位离开
音源的进一步优化；拖拽交接需要单独定位构建/绘制尖峰并保持 Hero 和手势语义。

## 协作交付

- `task_brief`：基于 v4.4.16，保持播放器视觉效果，修复 Android 大文件路径与
  连续切歌，并用真实组件及 USB 真机测量。
- `dispatch`：`read_only` 为 Flutter 动画与移动播放顾问；
  `writer_sequence` 为 `player_performance_writer` 初稿后交接主任务完成测量、
  音频、动画和验证，任一时刻仅一个写入者。`writer` 为主任务。
  `skipped`：其他角色与既有职责重复，或不涉及此次平台、依赖及发布范围。
- `agents`：
  - `name: player_animation_map`；`focus`：动画边界与隐藏页更新；`result`：
    确认隐藏字幕仍订阅播放行并触发重建，采用延后更新；`risks`：设备尾部帧波动；
    `next_step`：交接尖峰的构建/绘制分段分析。
  - `name: audio_switch_path`；`focus`：移动端音源切换；`result`：确认整文件复制
    与取消/并发缺口；`risks`：原生阶段尚未细分；`next_step`：缓存及离开音源计时。
  - `name: player_performance_writer`；`focus`：测量初稿与请求状态复核；`result`：
    完成交接并指出恢复播放分支，已修复和回归；`risks`：人工实听未确认；
    `next_step`：记录实听反馈。
- `implementation_plan`：真实场景与分段计时 → 原文件播放及请求协调 → 隐藏页
  更新范围 → 回归、同机五轮与换源策略对比。
- `verification`：以上测试、性能表及限制共同构成交付结果。
- `dependency_risks`：保持现有依赖与版本；无新增依赖。
- `conflicts`：`[]`。
- `handoff`：代码、测试与可重复运行工具已在工作区；继续定位尚未达标的尾部帧
  和缓存/离开音源阶段，使用相同测试口径验证。
