# Android 视频首帧等待

Android 视频详情改为在正文就绪后读取 HTML，随后释放源站网页。
同包模拟对照中，可见首帧等待中位数从 15.515 秒降至 13.295 秒。
播放器挂载中位数从 11.261 秒降至 5.793 秒。
37 项验证会话和浏览器队列回归已通过。

## 改动

- 详情导航接受新文档的 `interactive` 状态，减少等待整页资源加载的时间。
- 导航前标记旧文档，避免把同 URL 的旧页面当作新结果。
- 继续检查源站、文档根节点和 Cloudflare 挑战状态。
- 主文档错误可打断尚未返回的导航调用。
- 连接验证继续等待完整页面，文档释放沿用原有顺序。

代码见 [missav_verification.dart](../../lib/src/videos/missav_verification.dart)。
正文就绪后，页面仍须通过验证检查。
读取或导航失败时，浏览器先停止导航，再释放网页。

## 定位证据

源站详情浏览器等待了正文以外的网页资源。
原代码先等 `onPageFinished`，再读取 HTML。
等待期间，网页还请求广告和网页播放器自己的媒体分片。

一轮真机记录中，从详情文档请求开始计算：

| 浏览器事件 | 时间 |
| --- | ---: |
| 文档对象模型（DOM）就绪 | 1.809 秒 |
| 整页加载完成 | 8.644 秒 |
| 两者相差 | 6.835 秒 |

这些时间来自浏览器原生事件时钟。
该间隔发生在应用播放器挂载前。

## 修复前基线

测量日期为 2026-10-27。
设备为 Android 12 真机 ABR-AL60，运行普通 Debug 应用。
使用同一个源站 HTTP Live Streaming（HLS）样本。
每轮固定从 3 秒续播，结束后恢复原续播进度。

| 轮次 | 播放器挂载观测时间 | 可见首帧等待 |
| --- | ---: | ---: |
| 1 | 11.857 秒 | 16.876 秒 |
| 2 | 7.432 秒 | 11.310 秒 |
| 3 | 10.239 秒 | 14.456 秒 |
| 中位数 | 10.239 秒 | 14.456 秒 |

计时从调用视频卡片所用的详情入口开始。
播放控件准备完成后，测量脚本调用播放按钮所用的方法。
脚本从播放器截图的 16 个采样点判断非黑画面。
采样点的红、绿、蓝任一通道值大于 40 时，记为非黑像素。
至少 8 个采样点出现非黑像素时，记录可见首帧。

轮询和读图会增加观测延迟。
表中结果包含调试与采样开销，不能代表正式版性能。
视频自带黑场也会影响非黑画面计时。
完整传输、输出表面就绪和可见首帧采用不同指标。

本机原始记录位于 `build/diagnostics/video-first-frame/`。
基线文件为 `detail-fixed-before-1.json` 至 `detail-fixed-before-3.json`。
浏览器事件保存在对应的 `navigation-fixed-before-*.json`。

## 同包真机对照

2026-10-27 的复测已完成，两组各保留 3 次。
本轮串行重建 `lib/main.dart` 的 Android arm64 普通 Debug 包。
安装前确认包名为 `com.meteor.kikoeruflutter.debug`。
运行中的等待函数已确认包含 `documentOnly` 参数。

两组使用同一个包和进程，继续播放同一个源站样本。
样本标识为 `rlmp-021-uncensored-leak`，每次从 3 秒续播。
核对后，两组的以下条件相同：

- `Source` HLS 流的完整本地转发地址相同。
- 解码画面均为 1920 × 1080，播放速度均为 1 倍。
- 自动播放、自动全屏和自动画中画均关闭。
- 画面适配、超分辨率、字幕和翻转设置相同。
- 采样时应用在前台，手机保持唤醒并固定竖屏。

对照组将应用私有导航标记保留至 `window.load`。
正文组使用应用现有的提前读取条件。
对照只模拟等待整页加载的影响。
结果不能等同于两个应用版本的提速比例。

两组均从卡片详情入口计时，播放器准备后触发播放。
计时采用主机的单调时钟。

| 条件 | 轮次 | 播放器挂载观测时间 | 可见首帧等待 |
| --- | ---: | ---: | ---: |
| 等待整页加载 | 1 | 7.964 秒 | 12.673 秒 |
| 等待整页加载 | 2 | 11.420 秒 | 16.195 秒 |
| 等待整页加载 | 3 | 11.261 秒 | 15.515 秒 |
| 提前读取正文 | 1 | 6.913 秒 | 13.911 秒 |
| 提前读取正文 | 2 | 5.793 秒 | 13.295 秒 |
| 提前读取正文 | 3 | 4.845 秒 | 11.878 秒 |

| 指标中位数 | 等待整页加载 | 提前读取正文 |
| --- | ---: | ---: |
| 播放器挂载观测时间 | 11.261 秒 | 5.793 秒 |
| 可见首帧等待 | 15.515 秒 | 13.295 秒 |
| 触发播放后至可见首帧 | 4.474 秒 | 6.806 秒 |

正文组的播放器提前 5.468 秒挂载。
可见首帧中位数减少 2.220 秒。
正文组触发播放后的等待反而多了 2.331 秒。
播放器提前挂载的收益没有全部转化为首帧收益。

3 次正文组均在源站主文档触发 `load` 前停放网页。
3 次对照组均在 DOM 就绪时保留导航标记。
对照组均在 `load` 释放标记后挂载播放器。
每次仅出现 1 次目标详情导航和 1 次 DOM 就绪事件。

本轮使用 `adb screencap` 采样手机实际显示的画面。
采样矩形取自视频画面的全局位置。
非黑判据沿用 16 个点、至少 8 个非黑点。
全部 6 次均保留最后一张黑图和第一张可见图。
逐图核对后，黑图中的视频区域仍为黑色。
可见图显示同一段 3 秒续播画面。
截图时，播放器位置均已到达 3000 毫秒。

表中首帧时间取自第一张可见截图的返回时刻。
最后黑图与第一张可见图之间的观测区间为 1.300～1.458 秒。
两组结果有重叠，3 次样本不足以证明稳定的提速比例。
历史基线的界面和截图方式不同，不能直接计算版本收益。

本轮原始记录位于 `build/diagnostics/video-first-frame/`：

- 正文组：`paired-complete-e1.json` 至 `paired-complete-e3.json`。
- 对照组：`paired-complete-c2.json` 至 `paired-complete-c4.json`。
- 汇总与条件断言：`paired-complete-summary.json`。
- 黑图和可见图：对应记录的 `-last-black.png` 与 `-visible.png`。

全部采样结束后，样本的原续播进度已恢复为 0 毫秒。
USB 常亮、自动旋转和方向设置已恢复原值。
临时浏览器脚本已移除。

## 验证边界

以上数据来自 Debug 模式，不能代表正式版性能。
播放后的等待仍需继续定位。

正式对照前，Debug 进程曾在采样结束时发生 1 次原生崩溃。
系统记录为 `SIGSEGV`，栈顶位于 `libflutter.so`。
崩溃原因尚未确定，记录见 `resume-native-crash.log`。
崩溃记录未纳入对照，重启后重新确认了运行代码。
最终 6 次样本来自同一个新进程。

保存会话恢复与详情首载重叠时，可能重复读取详情。
本轮保留的真机样本没有触发该分支。
该分支保留现有会话切换行为。

浏览器媒体转发的既往实验见[确认等待实验](video-relay-performance.md)。
