# 本地音频字幕生成

本方案定义 KikoFlu 首版音频字幕生成的实现范围。架构与隐私决定见
[ADR 0003](../adr/0003-local-audio-subtitle-generation.md)，领域术语使用
[CONTEXT.md](../../CONTEXT.md) 中的 Audio Subtitle Generation。

## 实现目标

- 覆盖 Android、iOS、Windows、macOS、Linux，保留现有 iOS 13 下限和 Linux
  x64、ARM64 发布目标。
- 首版识别日语，生成字幕支持 MP3、WAV、FLAC。其他音频格式显示暂不支持生成
  字幕，不改变其现有播放行为；批量任务记录这些文件并继续处理支持的文件。
- 模型首次按需下载，后续复用本地模型。原始音频只在当前设备上识别。
- 保存带时间轴的日文 SRT，加载后可以使用现有字幕翻译操作。翻译由用户手动
  触发，字幕文字可以提交给现有在线翻译服务，翻译保存行为沿用现有设置。

## 两个入口

播放器复用字幕界面左下角的字幕选择按钮作为单条入口。当前音频已有可用
字幕时，沿用现有字幕选择界面；没有可用字幕时，点击该按钮进入当前音频的
本地字幕生成流程。任务绑定点击时的原音频；生成完成时，只有播放器仍是
该音频才自动加载，切换曲目不改变任务的保存对象。

在线和离线作品详情页的音频资源标签提供批量生成操作。开始时使用该标签
当前实际展示的完整音频列表，沿用音频格式、字幕语言和效果音等现有偏好，
不以滚动视口内的行数限定范围。批量生成跳过已有可用字幕的音频，包括作品
字幕、字幕库匹配和以前生成的字幕。

## 音频来源与任务

优先复用本地导入文件、已完成下载或完整缓存；在线播放的部分缓存不足以
作为识别输入。缺少完整文件时，允许复用现有下载通路将音频下载到本地。

单条与批量入口共用生成队列，一次识别一条音频，同一音频不重复进入队列。
任务提供进度与取消操作。单条失败记录失败阶段，批量继续处理后续音频；结束时
汇总成功、已有字幕、不支持格式和失败的数量。

页面或曲目切换后，任务继续运行。关闭应用后停止剩余任务并保留已经完成
的字幕，下次由用户手动启动。移动系统暂停应用进程时，识别进度不能保证
持续推进；本规则不要求新增系统后台常驻任务。

## 保存与关联

生成的原文字幕持久保存到现有字幕库，沿用其索引刷新和播放器加载流程。
文件关联使用原音频已有的作品与文件身份，区分不同作品或不同目录中的同名
音频；文件名相同不足以判定为同一条音频。保存时保留已有字幕，完整结果
保存成功后才作为可加载字幕发布，关闭应用或取消任务不发布未完成结果。

服务端音频使用作品 ID 和原始 hash 关联，完整下载的作品元数据保留原始
文件树，离线重新播放仍使用同一 hash。本地扫描生成的 `local:<relativePath>`
使用规范化的绝对本地路径关联，避免不同根目录的同名文件共用生成字幕。

## 本地识别路径

使用 sherpa_onnx 官方 Flutter FFI 和日语专用 ReazonSpeech 模型；共享的
miniaudio C 解码桥把本地音频分块转换成识别所需的单声道 PCM。模型初始化
与解码、推理在专用工作 isolate 中运行，播放器交互不等待同步 native 推理。

依赖固定为 `sherpa_onnx 1.13.8`、本项目的 `local_audio_decoder` 插件及其
内置 `miniaudio 0.11.25`。首次下载 ReazonSpeech int8 的 encoder、decoder、
joiner、tokens 和 Silero VAD，共约 161 MB，保存在应用支持目录的
`local_audio_subtitles/ja_reazonspeech`。完成的模型文件可重复使用；失败或取消
时删除当前 `.part` 文件，下次手动生成时重试尚未完成的文件。

长音频分块解码，按语音区段识别。字幕时间轴以原音频中的区段位置为依据，
停止请求在区段之间生效；不把整条长音频的 PCM 同时保留在内存中。

解码每次读取 10 秒、16 kHz 的单声道 float PCM；Silero 每次接收 512 个采样，
跨读取保留不足一个窗口的余量。语音区段最长 12 秒，VAD 缓冲区为 24 秒，
识别使用两个线程。模型加载和单个 native 推理调用结束后才能响应取消。

原文保存于字幕库的 `已保存/生成字幕` 目录，每条结果有独立子目录。
`SubtitleDatabase` 保存原音频身份到相对字幕路径的关联，目录索引重建后仍能
找到生成结果。取消生成会释放对共享音频下载的等待，下载队列中的音频仍可
继续下载并供播放或后续生成复用。

## 验证记录

Windows x64 使用模型公开的 13.433 秒日语 WAV 样本及转换得到的 MP3、FLAC，
实际执行解码、ReazonSpeech 推理、SRT 生成和现有字幕解析器读取；三种格式
均得到非空日文字幕，首条字幕在两秒内，末条时间不超过音频长度。识别取消
也已通过 native 路径验证。模型和音频就绪后，识别阶段只使用本地文件。

| 格式 | 处理耗时 | 字幕条数 | 末条结束时间 |
| --- | ---: | ---: | ---: |
| WAV | 4.790 秒 | 2 | 12.844 秒 |
| MP3 | 4.707 秒 | 1 | 12.764 秒 |
| FLAC | 4.368 秒 | 2 | 12.844 秒 |

该次 Windows `flutter_tester` 进程采样的峰值工作集约 561 MiB，包含 Flutter
测试宿主和模型，不能作为手机内存或耗时的测量结果。

- 122 项相关自动化测试通过，覆盖模型失败重试与取消、跨块 VAD 输入、SRT
  时间轴、字幕库持久关联、队列串行与去重、批量失败后继续、生成时切曲、
  共享下载等待释放及已有字幕选择/加载/交互和音频资源标签的回归。
- 界面测试覆盖 40 条音频的完整筛选列表和父目录、已有字幕沿用选择界面、
  无字幕使用原按钮生成、关闭面板任务继续，以及 780×360 横屏、1.3 倍字号
  下的滚动与取消操作。
- 所有本次新增与修改的 Dart 文件静态检查通过；本地化资源生成通过。
- Windows x64 Debug 编译与 INSTALL 通过，包中包含解码、Sherpa C API 和
  ONNX Runtime DLL。当前 CMake 4.3.1 与已有 `smtc_windows 0.1.3` 的符号链接
  目录解压不兼容，打包验证使用 CMake 3.22.1 解压该依赖后执行 INSTALL。
- Android Debug APK 构建通过，包中包含 ARM64、ARMv7、x86_64 的解码、Sherpa
  和 ONNX Runtime 库；新增的三类 64 位 native 库均验证为 16 KB ELF 对齐。

## 已知限制与后续验证

iOS 13、macOS、Linux x64/ARM64 的配置已接入，当前 Windows 环境未执行这些
目标的构建与运行。Android 目前完成打包验证，尚未在实际手机上测量内存、
耗时和后台暂停行为。

公开日语语音片段的结果证明本地识别和字幕流程可运行，不能替代真实音声的
准确率评估。耳语、气声和长时间音频的文本与时间轴仍需在实际设备试听校对；
应先完成这些样本检查，再考虑调整 VAD 或更换模型。

## 实施与验收

1. 先接通共享解码桥、模型下载和本地识别。在 Windows 上分别用真实 MP3、WAV、
   FLAC 日语片段验证解码、识别和 SRT 解析，记录内存峰值及处理耗时。短链
   跑通后再接入生成队列与两个界面入口。模型和完整音频已就绪时，断网仍能
   生成字幕；转写流程不发送原始音频。
2. 验证完整文件复用与按需下载、模型下载失败后的重试、字幕缺失与已有字幕
   的批量分支，以及取消和单条失败后队列继续处理的行为。
3. 验证生成期间切换曲目或页面、不同作品与目录的同名音频、字幕保存及索引
   刷新、中文及日文文件路径、重新播放时加载，以及手动翻译和已有翻译保存偏好。
4. 按原有平台和架构构建 native 产物，并完成 Android、iOS、macOS、Linux
   x64/ARM64 的格式与识别检查。Windows 通过不能代替其他目标的构建和运行验证。
5. 以真实日语音声试听校对文本与时间轴，重点检查耳语、气声、静音和长片段。
   模型准确率及实际机型耗时以测量结果为准。

## 现有代码的复用位置

- `WorkResourceTabs` 与 `PlayerAudioVariantClassifier.selectBest`：音频标签的列表范围。
- `AudioFileUrlResolver`、`AudioStreamCache`、`DownloadService`：本地文件和完整下载。
- `SubtitleLibraryService` 与 `SubtitleDatabase`：字幕保存后的索引与查询。
- `PlayerLyricsSurface` 与 `showPlayerSubtitlePickerSheet`：播放器左下角的字幕选择入口。
- `LyricController` 与 `LyricParser`：字幕加载、解析、显示和既有翻译流程。
